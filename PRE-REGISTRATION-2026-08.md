# Pre-Registration — August 2026 Agent-Trial Re-Run

**Written:** 2026-08-16, before either session in this re-run has been executed.
**Author intent:** lock the interpretation in advance so the eventual result is a finding, not a story chosen after the fact.

## Why this document exists

The July 2026 benchmark report's credibility rested on publishing a result that made Depwire look bad: "Depwire basic — tools available but no workflow guidance — performed worse than no Depwire at all." That negative result is now known to be confounded. It was measured against a parser (`depwire-cli` pre-1.13.0/1.14.0) that:

- fabricated 23,446 wrong same-file `calls` edges on `drizzle-orm` alone (member-expression calls resolving to nonexistent local symbols),
- could not resolve monorepo cross-package imports at all,
- had at least one exponential depth-score hang and other correctness bugs since fixed.

Re-running the trial is only worth doing if the interpretation of both possible outcomes is fixed **before** the numbers exist. A framing chosen after seeing the result is not a finding — it is a narrative.

## 1. What is being tested

The controlled comparison is **within-August only**:

```
depwire_basic   vs   depwire_guided   vs   no_depwire
```

All three arms run against the **same current graph**: `depwire-cli@1.14.1`, repo `payloadcms/payload` (`packages/payload`), commit `1545e8758be9a887f3f1020592b3117adb54dd5f`, 7,378 symbols, 6,765 edges, zero fabricated member-call edges, full monorepo import resolution.

**The July-to-August comparison is explicitly NOT controlled.** Two variables changed between July and August: the workflow guidance given to the agent, AND the underlying graph the tool served. A clean or dirty result in August does **not**, by itself, isolate the effect of workflow guidance from the effect of fixing the parser. July is **historical context only** — it is not a fourth arm and must not be presented as one. Any write-up of this re-run must state this plainly rather than let a reader infer a controlled A/B where none exists.

## 3. The two conclusions, written verbatim now

One of these two paragraphs will be used verbatim (mode-name substitutions only) in whatever gets published, depending on which the numbers match:

**A. If `depwire_basic` still underperforms `no_depwire`:**

> The negative result is robust. It survives against a graph with zero fabricated edges and full monorepo resolution, so the cause is missing workflow guidance, not bad data.

**B. If `depwire_basic` no longer underperforms `no_depwire`:**

> The July negative result was measuring a parser bug, not a tool limitation. We found this by auditing our own benchmark.

No other framing is authorized for describing this specific comparison. If the result is ambiguous (see Section 6), neither conclusion is used — the run is reported as inconclusive per the invalidation rule instead.

## 4. Publication commitment

Both sessions are run. Both are published. This holds regardless of which arm comes out less flattering for Depwire — that symmetry is what made the July report credible, and it is the only thing that preserves it into August. There is no cherry-picking which arm to report, no discarding a session for producing an inconvenient score outside the invalidation rule in Section 6, and no re-running an arm to get a better number.

## 5. Known confounds, declared in advance

- **July vs. August is not a controlled A/B.** The underlying graph changed between the two, not just the guidance given to the agent (see Section 1).
- **`.depwire/AGENTS.md` is stale** in the benchmark repo: it still reports "Auto-generated by Depwire v1.8.6 — 645 files, 9,292 symbols, 3,511 cross-file edges" and is injected as system-prompt context in **both** `depwire_basic` and `depwire_guided` modes. Live `connect_repo` / `get_architecture_summary` MCP calls during the session report the real current graph (7,378 symbols, 6,765 edges), so the agent discovers the true numbers during the session — but it starts from a wrong number in its initial context. Because this stale file is injected **identically in both Depwire arms**, it does not bias the within-August `depwire_basic` vs. `depwire_guided` comparison. It is nonetheless a real difference from the July setup and must not be left implicit in any write-up.
  - Attempting to regenerate `AGENTS.md` via `depwire docs --update` was tried ahead of this re-run and **crashed with a V8 out-of-memory fatal error** (heap grows past 4GB then aborts) on this 691-file repo. Filed separately as [depwire/depwire#15](https://github.com/depwire/depwire/issues/15). This is why the stale file was left in place rather than regenerated.
- **n=1 per arm.** Each mode is a single human-driven agent session. Single-session trials are high variance — a single run's outcome may reflect agent nondeterminism, session-specific mistakes, or luck, not a stable property of the mode. Conclusions A and B above should be stated with that caveat attached, not as a definitive resolution from one data point per arm.

## 6. What would invalidate a session

Defined now, before any session runs, so a session cannot be discarded after the fact merely because its number is inconvenient. A session is **invalid and must be re-run** (not silently redone and only the second result kept — the first attempt and its numbers are recorded too) only if:

- the agent explicitly fails to complete the task (stops, errors out, or reports it cannot finish) rather than submitting a completed — even if wrong — attempt;
- the harness itself crashes mid-run (`measure.sh`, `pnpm build`, or the MCP server process dies before the agent finishes, as opposed to the agent's own edits causing `tsc` or test failures — those are valid outcomes, not invalidating ones);
- a rate limit or API outage interrupts the session before the agent reaches a stopping point;
- the wrong branch/commit/task was used (harness misconfiguration, not agent or tool behavior).

A session is **not** invalidated by: a low correctness score, a `tsc` failure, a test failure, high cost, high tool-call count, or the agent performing worse than expected. Those are the measurement, not a reason to discard it.
